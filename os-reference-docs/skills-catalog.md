## Description

Single reference for every skill, system and agent on this machine. The skills table comes first, then the systems table and the agents table.

The skills table records, for every skill, who owns it, which system it belongs to, what type it is, who can start it, where its file lives, where OpenCode loads it from, whether the copies agree, and what it does. Every skill on this PC has a row. A skill that is installed has a plain row. A struck-through row is a skill that is on this PC but not installed. A skill that is not on this PC has no row.

The columns mean the following.

- **Owner** is the GitHub account that publishes the skill. Skills written for MyBizz OS have the owner `mybizz`.
- **System** is the system the skill belongs to or configures. A skill that is a system in its own right carries its own name. When the system has documents, the name is its folder name under `C:\mybizz\mybizz-config-docs`. The word `standalone` is not used.
- **Skill Name** is the `name` field in the skill's frontmatter, which is the name OpenCode uses.
- **Skill Type** is `Operational` for a skill that does work and `Support` for a skill that prepares the input another skill consumes.
- **Invocation** is `User` when only the user can start the skill, `Agent` when only an agent can, and `Both` when either can. In OpenCode every installed skill is `Both`, because OpenCode does not act on the frontmatter settings that restrict this.
- **Source path** is the file the skill is maintained from. When no separate source exists, it is the installed file itself.
- **Installed path** is where OpenCode loads the skill from, with several paths separated by semicolons, or `not installed`.
- **Status** is `OK`, or one or more of the following separated by semicolons: `Not installed` (OpenCode does not load it), `Installed more than once` (OpenCode reaches it through more than one path), `Installed copy missing` (an installed path has no file), `No source copy` (no separate source exists) and `Copies differ` (an installed copy's content differs from the source). `OK` means installed once with content identical to its source. Content is compared below the frontmatter, because source documents carry documentation frontmatter (`title`, `doc-id`, `updated`) and installed skills carry skill frontmatter (`name`, `description`) by design.
- **Skill Description** is the `description` field of the installed copy, or of the source when the skill is not installed.

## Systems

Every system on this PC has a row. A system is a program, script, database or process that skills and agents depend on. A skill that is also a system appears in both tables.

- **Owner** is the GitHub account that publishes the system. Systems MyBizz built have the owner `mybizz`.
- **System** is the system's name. When the system has documents, it is the folder name under `C:\mybizz\mybizz-config-docs`.
- **Kind** is what the system is.
- **Description** is what the system does.

## Agents

Every agent MyBizz wrote or installed from outside has a row. OpenCode's own agents are part of OpenCode and have no row.

- **Owner** is the GitHub account that publishes the agent. Agents MyBizz wrote have the owner `mybizz`.
- **Agent** is the agent's name, which is its file name.
- **Scope** is where the agent works.
- **Mode** is `Primary` for an agent the developer works with directly, or `Subagent` for an agent another agent calls.
- **File** is where OpenCode loads the agent from.
- **Description** is what the agent does.

## Documentation

A system or skill has documents only when MyBizz built it or set it up in its own way. Its documents are the four that mb-sysdoc-creator writes, in its own folder under `C:\mybizz\mybizz-config-docs`. A vendor skill used as it comes has no documents, and its catalog row is its record.

## memory-governor naming exemption

The `memory-governor` suite folder and system name lack the `mb-` prefix but stay exactly as named. The system is deeply entrenched (PDLF among others); renaming effort is not worth the outcome. Do not rename.
