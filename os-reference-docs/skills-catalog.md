## Description

Single reference for every skill on this machine: who owns it, which system it belongs to, what type it is, who can start it, where its file lives, where OpenCode loads it from, whether the copies agree, and what it does. Every skill is either installed or struck through. A struck-through row is a skill that is not used on this system and is not installed, and the note at the bottom of this document gives the reason. No skill is left undecided.

The columns mean the following.

- **Owner** is the GitHub account that publishes the skill. Skills written for MyBizz OS have the owner `mybizz`.
- **System** is the system the skill belongs to or configures, spelled as that system's folder name under `C:\mybizz\mybizz-config-docs`. A skill that belongs to no larger system is its own system and carries its own name. The word `standalone` is not used.
- **Skill Name** is the `name` field in the skill's frontmatter, which is the name OpenCode uses.
- **Skill Type** is `Operational` for a skill that does work, `Config` for a skill that examines a system's configuration and keeps it healthy (created by `mb-config-manager`), and `Support` for a skill that prepares the input another skill consumes.
- **Invocation** is `User` when only the user can start the skill, `Agent` when only an agent can, and `Both` when either can. In OpenCode every installed skill is `Both`, because OpenCode does not act on the frontmatter settings that restrict this.
- **Source path** is the file the skill is maintained from. When no separate source exists, it is the installed file itself.
- **Installed path** is where OpenCode loads the skill from, with several paths separated by semicolons, or `not installed`.
- **Status** is `OK`, or one or more of the following separated by semicolons: `Not installed` (OpenCode does not load it), `Installed more than once` (OpenCode reaches it through more than one path), `Installed copy missing` (an installed path has no file), `No source copy` (no separate source exists) and `Copies differ` (an installed copy's content differs from the source). `OK` means installed once with content identical to its source. Content is compared below the frontmatter, because source documents carry documentation frontmatter (`title`, `doc-id`, `updated`) and installed skills carry skill frontmatter (`name`, `description`) by design.
- **Skill Description** is the `description` field of the installed copy, or of the source when the skill is not installed.

## memory-governor naming exemption

The `memory-governor` suite folder and system name lack the `mb-` prefix but stay exactly as named. The system is deeply entrenched (PDLF among others); renaming effort is not worth the outcome. Do not rename.

## Skills not used on this system

The skills struck through in the table are not used on this system. Each one either depends on something this PC does not have, so it can never run here, or is a duplicate written for a different agent program.

`setup-cowork`, `schedule` and `consolidate-memory` need Claude Cowork, Anthropic's desktop app, which this PC does not run. They come from that app's own skill folder and drive features that exist only inside Cowork.

`git-guardrails-claude-code` needs Claude Code. It sets up Claude Code hooks that block dangerous git commands, so without Claude Code there is nothing for it to configure.

`claude-handoff` needs Claude Code. It hands the conversation to a fresh background agent by starting a new Claude Code session.

`claude` (gstack) needs Claude Code. It gets a second opinion by calling the Claude Code program.

`ios-qa`, `ios-fix`, `ios-design-review`, `ios-clean` and `ios-sync` are not used. `ios-qa`, `ios-fix` and `ios-design-review` need a Mac with Xcode 16 or later and a real iPhone running iOS 16 or later, paired with that Mac; this PC runs Windows and WSL, so the iOS testing they rely on cannot run. `ios-clean` and `ios-sync` only remove or regenerate the debug bridge that `ios-qa` installs into an iOS app, so without `ios-qa` they have nothing to work on.

`gstack-openclaw-ceo-review`, `gstack-openclaw-investigate`, `gstack-openclaw-office-hours` and `gstack-openclaw-retro` are gstack's versions written for OpenClaw, a different agent program. This system runs OpenCode, and the same methods are already installed as the normal gstack skills `plan-ceo-review`, `investigate`, `office-hours` and `retro`.

All 80 skills from the GBrain clone (owner `garrytan`, system `gbrain`) are not used. GBrain is used here as the search index over the documentation repositories, not as a personal knowledge base. Most of its skills run a personal knowledge base, taking in meetings, email, voice notes, books, media and people, so they have nothing to work on here. Its administration skills would let an agent set up, upgrade, migrate or repair GBrain; those actions are reserved for the developer and are covered by `mb-config-gbrain` and the GBrain sync script. Its search skills would give agents a second set of rules for using GBrain alongside `memory-governor` and `mb-submit-memory`, and one job must have one set of rules.

`pdf`, `pptx` and `skill-creator` (owner `anthropics`) are not used. The user does not require them, and alternatives exist.

`docx` and `xlsx` (owner `anthropics`) are not used. Their licence allows use only within Anthropic's own services and forbids keeping copies outside them, so they cannot be used in OpenCode on this PC. `minimax-docx` and `minimax-xlsx` (owner `MiniMax-AI`, MIT licence) are installed instead.
