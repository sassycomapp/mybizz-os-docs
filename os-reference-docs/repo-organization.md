## Notes

**Verified against the machine:** `git remote` of every repository, `gbrain sources list`, the OpenCode project list, the `.cupcake` folders and a Cupcake evaluation from every OpenCode project folder.

**GBrain source:** the source id and its federation state. `federated`: appears in every other source's default search and may write links into other sources. `unset`: never set; the source stays out of other sources' searches, but a session working inside it can still read the federated sources. `isolated`: set explicitly with `gbrain sources unfederate`; cut off in both directions. Every documentation source is federated. The system code source `memory-governor-code` is `unset`. `— (code)` marks an application code repository, which is not a GBrain source.

**Application code is not in GBrain.** Agents read application code directly from the app folder, which is always current; an index of it would go stale between syncs.

**OpenCode project:** `Yes` for every repository an agent works in. App 2 of each business is a release of App 1, so no agent works in it. `project-template` is only ever copied. Third-party clones are read, never worked in. Two OpenCode entries are not repositories: `/`, OpenCode's own entry for folders outside any repository, and `/home/dev-p`, used only for Cupcake's skills-folder check.

**Cupcake:** `Fallback home` means the folder has no `.cupcake` skeleton, so Cupcake evaluates every agent action there through `~/.config/cupcake/fallback`, and every global rule applies. No project folder carries a skeleton. The one skeleton is `~/.cupcake`, the folder holding Cupcake's programs, which serves sessions started in `/home/dev-p`. `—` means no agent works there.

**Names:** every business has one project folder, `C:\dev\dev-{slug}\`, holding four code repositories and one project library: `{slug}-app1`, `{slug}-app2`, `{slug}-app3`, `{slug}-app5` and `{slug}-project-library`. The slugs are `mb-3-cs`, `mb-4-ecom` and `mb-5-pdlf`, all lowercase. App 4 (a client instance) lives on the client's own Anvil account and has no folder here. Each code repository is an Anvil app of the same name. `-code` appears only in some GBrain source ids. `pdlf-library` is a folder inside the `pdlf` repository, not a repository of its own.

**`mb-gbrain-searches`:** the record of every GBrain search Claude asks for and its results. It is not a GBrain source, because its results are copies of GBrain content. OpenCode agents only read it.

**`gbrain-repo`:** one repository, `sassycomapp/gbrain-repo`, checked out in two WSL folders by gstack: `/home/dev-p/.gstack` and its worktree `/home/dev-p/.gstack-brain-worktree`.

**Note on `anvil-agent-references-code`:** this source is a read-only clone of Anvil's own public repository, `github.com/anvil-works/anvil-agent-references`, at `C:\mybizz\anvil-agent-references`. Anvil publishes it. It is not one of the developer's repositories, and it has no GitHub repository of the developer's own. It is separate from `anvil-docs` in the source `default` (`project-library-global`), which is the developer's own compilation of Anvil documentation. The `-code` in its source id distinguishes it from the developer's own documentation folder `anvil-agent-references/` in `mybizz-config-docs`. The source is isolated, so it is searched only when named explicitly. It is updated by hand (`git -C /mnt/c/mybizz/anvil-agent-references pull`); the standing sync script does not pull.

**Commit hook and `commit-all.sh`:** they apply to every documentation repository: `default`, `dev-root-hub`, `mb-3-cs-project-library`, `mb-4-ecom-project-library`, `mb-5-pdlf-project-library`, `mb-archify-scope`, `mb-close-out`, `mb-compile-rules`, `mb-memory-system-diagnostic`, `mb-project-docs`, `mb-sentinel-review`, `mb-submit-memory`, `mb-sysdoc-creator`, `mybizz-config-docs`, `mybizz-os-docs`, `data-mybizz-mgt` and `pdlf`. They also cover the scripts repository, `mybizz-scripts`. They do not cover `mb-gbrain-searches`, whose own script commits and pushes it so that the hook never rewrites the recorded GBrain output. They do not cover the app code repositories, the Anvil clone, `project-template`, `gbrain-repo` or the memory governor's folder.

**Branch:** every repository works on `main`, except the Anvil app code repositories, which work on `master` because Anvil syncs that branch.
